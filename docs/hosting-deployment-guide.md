# راهنمای جامع تجمیع خودکار اخبار — تست، استقرار روی هاست و کار با پنل

> این سند دقیقاً برای نیاز شما نوشته شده: تست راحت محلی، پوش امن روی هاست مشتری بدون خراب‌شدن اطلاعات، و راهنمای کامل کار با قابلیت‌های جدید.

---

## ۱) این ماژول دقیقاً چه کار می‌کند؟

### فلو ساده (بدون پیچیدگی)
```
لینک کانال مبدا (مثلا https://t.me/varzesh3)
  → هر X دقیقه (مثلا ۱۰ دقیقه) ربات بررسی می‌کند
  → اگر پیام جدید بود و تکراری نبود
  → متن پاکسازی می‌شود (حذف لینک/تگ در صورت انتخاب + فیلتر کلمات تبلیغاتی)
  → اگر تبلیغ بود → رد می‌شود و در لاگ با دلیل ثبت می‌شود
  → اگر خبر واقعی بود → عکس دانلود و ذخیره می‌شود
  → خبر با نام ادمین/دسته‌بندی/تگ‌های انتخابی شما در سایت منتشر می‌شود
  → همان خبر به کانال(های) مقصد شما (ربات‌های تلگرام/بله که ادمین کرده‌اید) ارسال می‌شود
  → همه مراحل در بخش لاگ‌ها قابل رصد است
```

### کجا دخالتی در اطلاعات قبلی ندارد؟
- هیچ جدول قدیمی حذف یا بازنویسی نمی‌شود.
- سه جدول جدید فقط اضافه می‌شوند: `source_channels` ، `destination_channels` ، `aggregated_messages`
- سه ستون فقط به `posts` اضافه می‌شود: `is_automated` ، `source_channel_id` ، `original_source_url` — همه `nullable` یا با مقدار پیش‌فرض، پس پست‌های قدیمی دست نمی‌خورند.
- همه `foreign key`‌ها `nullOnDelete` / `cascadeOnDelete` امن هستند.
- توکن ربات‌ها با `encrypted` ذخیره می‌شود (در دیتابیس قابل خواندن نیست).

## ۲) پیش‌نیاز روی هاست

- PHP 8.2+ ، MySQL ، Laravel 12
- یک توکن ربات تلگرام برای **خواندن** کانال‌های مبدا (اختیاری اما برای تلگرام لازم است) — از `@BotFather` با `/newbot` بسازید و در `.env` بگذارید:

```env
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
```

> برای بله، توکن هر مقصد جداگانه در پنل وارد می‌شود (نیازی به `.env` نیست).

## ۳) تست محلی — گام به گام (۲ دقیقه)

```bash
# 1) مایگریشن (فقط جداول جدید را می‌سازد، داده‌های قبلی سالم می‌ماند)
php artisan migrate --force

# 2) تست خودکار (۳۰ تست — شامل تجمیع اخبار)
php artisan test
# یا فقط همین ماژول:
php artisan test --filter=NewsAggregatorTest

# 3) چک سلامت مسیرها و ویوها
php artisan route:list --path=aggregator
php artisan view:cache
php artisan config:clear
```

### تست دستی پنل (بدون نیاز به تلگرام واقعی)
1. وارد پنل شوید: `/didebaneshahr/admin` با کاربر `super-admin`
2. منوی جدید **تجمیع اخبار** را ببینید (۴ زیرمنو).
3. **منابع (کانال‌ها)** → لینک یک کانال تستی وارد کنید مثلاً `https://t.me/varzesh3` ، بازه `10` دقیقه، در کادر فیلتر بنویسید:
   ```
   تبلیغات
   فروش ویژه
   ```
   تیک «حذف لینک‌ها» و «حذف تگ‌ها» را روشن بگذارید → ذخیره.
4. **ربات‌های انتشار** → یک ربات تستی اضافه کنید (نام دلخواه، پلتفرم تلگرام، توکن ساختگی `123:ABC`، شناسه کانال `@my_test_channel`) → ذخیره (توکن رمزنگاری می‌شود).
5. **تنظیمات انتشار در سایت** → یک ادمین، یک دسته‌بندی و چند تگ انتخاب و ذخیره کنید.
6. **لاگ‌ها** → هنوز خالی است؛ بعد از اجرای دستور بعدی پر می‌شود.

### اجرای دستی پولینگ (بدون cron)
```bash
php artisan aggregator:poll
# سپس لاگ‌ها را در پنل ببینید — هر پیام جدید، تبلیغ ردشده یا خطا با دلیل ثبت شده
```

> اگر `TELEGRAM_BOT_TOKEN` ست نباشد، پولینگ بدون خطا رد می‌شود (لاگ خطا نمی‌دهد، فقط چیزی منتشر نمی‌کند) — برای تست واقعی، توکن واقعی بگذارید.

## ۴) استقرار امن روی هاست مشتری — بدون ریسک

> این مراحل عیناً ترتیب امن پیشنهادی است. اگر همین ترتیب را بروید، اطلاعات مشتری خراب نمی‌شود.

### گام ۰ — بکاپ (حتماً قبل از پوش)
```bash
# از طریق هاست (cPanel > Backup یا phpMyAdmin > Export) یا SSH:
mysqldump -u dbuser -p dbname > backup_$(date +%F).sql
# و یک کپی از پوشه storage/app/public
```

### گام ۱ — پوش کد
```bash
git pull origin main
# یا اگر با FTP آپلود می‌کنید، فقط فایل‌های جدید را جایگزین کنید
```

### گام ۲ — نصب وابستگی‌ها (اگر composer روی هاست دارید)
```bash
composer install --no-dev --optimize-autoloader
```

### گام ۳ — مایگریشن امن
```bash
php artisan migrate --force
# خروجی باید 3 مایگریشن تجمیع اخبار را DONE نشان دهد:
# 2026_10_06_120000_create_aggregator_tables
# 2026_10_06_130000_simplify_aggregator_tables
# 2026_10_06_222534_add_aggregator_columns_to_posts
# هیچ DROP یا TRUNCATE روی جداول قدیمی اجرا نمی‌شود
```

### گام ۴ — کش و لینک استوریج
```bash
php artisan config:clear
php artisan route:clear
php artisan view:clear
php artisan storage:link   # فقط اگر قبلاً اجرا نشده
```

### گام ۵ — تنظیم `.env` روی هاست
```env
TELEGRAM_BOT_TOKEN=توکن_واقعی_ربات_تلگرام_برای_خواندن_کانال‌ها
APP_URL=https://domain.com
```
سپس:
```bash
php artisan config:cache
```

### گام ۶ — کرون جاب (اجرای خودکار هر دقیقه — خود اسکجولر هر ۱۵ دقیقه پول می‌کند یا هر X دقیقه که برای هر منبع ست کرده‌اید)
در cPanel → Cron Jobs یک کرون اضافه کنید:
```
* * * * * /usr/bin/php /home/USERNAME/public_html/artisan schedule:run >> /dev/null 2>&1
```
مسیر `php` و `public_html` را طبق هاست خود اصلاح کنید. از این به بعد هر دقیقه اسکجولر چک می‌کند و پولینگ طبق بازه هر منبع اجرا می‌شود.

### گام ۷ — تست نهایی روی هاست
1. وارد پنل شوید، ۴ منوی تجمیع اخبار را ببینید.
2. یک منبع و یک مقصد و تنظیمات سایت را ست کنید.
3. یک بار دستی اجرا کنید (SSH):
   ```bash
   php artisan aggregator:poll
   ```
4. به **لاگ‌ها** بروید — باید ردیف‌های جدید با وضعیت `منتشرشده` یا `رد/تبلیغ` ببینید. روی عنوان خبر کلیک کنید تا به صفحه سایت بروید.

### بازگشت در صورت مشکل (Rollback)
```bash
# فقط مایگریشن‌های تجمیع اخبار برمی‌گردد، بقیه دست نمی‌خورد
php artisan migrate:rollback --step=3
# و فایل بکاپ را ریستور کنید
mysql -u dbuser -p dbname < backup_2026-10-06.sql
```

## ۵) راهنمای کار با پنل — خیلی ساده

### منابع (کانال‌ها) — `/didebaneshahr/admin/aggregator/sources`
- **لینک کانال ***: فقط همین را وارد کنید. مثال: `https://t.me/varzesh3` یا `@varzesh3` یا `https://ble.ir/channel` — سیستم خودش نرمال می‌کند.
- **هر چند دقیقه بررسی شود؟**: عدد مثلاً `10` — اگر ۱۰ بگذارید، حتی اگر کرون هر دقیقه اجرا شود، هر منبع فقط هر ۱۰ دقیقه یک‌بار چک می‌شود.
- **کلمات فیلتر تبلیغات**: هر کلمه را در یک خط یا با کاما جدا کنید. مثال:
  ```
  تبلیغات، فروش ویژه، تخفیف، جهت سفارش
  ```
  هر پستی شامل یکی از این‌ها باشد، منتشر نمی‌شود و در لاگ با دلیل «کلیدواژه فیلتر: ...» می‌رود.
- **حذف لینک‌ها / حذف تگ‌ها**: دو چک‌باکس ساده — اگر روشن باشد، تمام `http://...` و `t.me/...` و `@منشن` و `#هشتگ` از متن خبر قبل از انتشار پاک می‌شود.
- ویرایش با دکمه مداد، حذف با سطل زباله.

### ربات‌های انتشار — `/didebaneshahr/admin/aggregator/destinations`
- **نام**: دلخواه (مثلاً «ربات اصلی تلگرام»)
- **پلتفرم**: تلگرام یا بله
- **توکن ربات ***: از `@BotFather` بگیرید — رمزنگاری‌شده ذخیره می‌شود (ویرایش: خالی بگذارید یعنی توکن قبلی بماند).
- **شناسه کانال مقصد ***: مثلاً `@my_news_channel` یا `-100123456789` — **ربات را حتماً در این کانال عضو و ادمین کنید** تا اجازه ارسال داشته باشد.
- تیک فعال/غیرفعال.

### تنظیمات انتشار در سایت — `/didebaneshahr/admin/aggregator/settings`
- **نویسنده/ادمین پیش‌فرض ***: خبرهای تجمیع‌شده به نام این ادمین در سایت نمایش داده می‌شود (برای کاربر عادی مثل خبر عادی است، فقط در پنل برچسب «خودکار» دارد).
- **دسته‌بندی پیش‌فرض ***: مثلاً «اخبار شهری»
- **تگ‌ها**: چند تگ اختیاری — همه پست‌های خودکار با این تگ‌ها `sync` می‌شوند.

### لاگ‌ها — `/didebaneshahr/admin/aggregator/logs`
- جدول کامل: منبع، شناسه پیام، وضعیت (`منتشرشده` سبز / `رد/تبلیغ` زرد / `خطا` قرمز / `در حال پردازش` خاکستری)، دلیل، لینک خبر سایت، تاریخ شمسی.
- فیلتر بالای جدول: فقط منتشرشده یا فقط تبلیغ‌ها را ببینید.
- اگر چیزی منتشر نشد، دلیلش را همین‌جا می‌بینید (مثلاً «کلیدواژه فیلتر: تخفیف» یا «محتوای خالی پس از پاکسازی»).

## ۷) سوالات متداول

**اگر کانال مبدا خصوصی باشد چه؟** ربات خواننده باید در آن کانال عضو باشد؛ در غیر این صورت `getUpdates` چیزی برنمی‌گرداند و لاگ خالی می‌ماند.

**روبیکا/ایتا/بله مبدا چطور؟** فعلاً کانکتور تلگرام کامل است؛ برای سایر پلتفرم‌ها لینک کانال را ثبت کنید، ساختار آماده است و کانکتور جدید فقط یک کلاس جدید است — بدون تغییر دیتابیس.

**چطور بفهمم ربات مقصد درست کار می‌کند؟** یک خبر تستی دستی بسازید، سپس `php artisan tinker` و `app(NewsAggregatorManager::class)->publishToDestinations($post)` را تست کنید و لاگ را چک کنید.
